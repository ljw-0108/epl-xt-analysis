# Canonical 2025/26 EPL pass-event contract

`data/processed/passes.csv` :
- `match_id`, `team`, `player`, `recipient`, `x`, `y`, `end_x`, `end_y`, `is_successful`
- Event data: **OpenPlay** `events_eng_2526.parquet`; ensure `comp=eng`, `season=2526`, `type=Pass`.
- `is_successful`: OpenPlay `outcome == Successful`.
- `x`, `y`, `end_x`, `end_y`: native OpenPlay 0..100, each team attacks toward x=100. Remove & count rows with missing or out-of-bounds coords; never impute values.
- `recipient`: left null. OpenPlay public event dictionary does **not** list a reliable recipient field. No exact pairwise connections can be claimed.
- Match ids and sha256 hashes are recorded after verified download in `config/source_manifest.json`. `verified_by_user=false` signals automatic checksum verification is **not** human review.
- 8×12 xT grid: Karun Singh open_xt_12x8_v1.json (older EPL baseline); not calibrated on 25/26.
- xT: for successful pass, `xT(end)-xT(start)`; failed pass value=0, signed result retained. This is a **pass-only** xT contribution metric.
- 26/27 result-only data is separate from 25/26 pass analytics and cannot be merged.

`data/processed/matches.csv` (generated by the downloader; hash in manifest `processed_matches_sha256`):
- `match_id`, `team`, `opponent`, `team_pass_rows` — one row per team per match. `opponent` is the other team present in that match's pass rows; a match without exactly two teams stops the pipeline. No date or home/away columns exist in the source, so none are produced.
- xT grid JSON SHA-256 is pinned (`GRID_SHA256` in `scripts/download_openplay_2526.py`); a changed file stops the pipeline.

## Passing metrics (`src/epl_xt/passing.py`)
- Metric geometry: OpenPlay 0..100 units are converted to a nominal 105 m x 68 m pitch (approximation; venue sizes vary).
- Direction: angle 0 deg = straight toward x=100. |angle| < 45 forward, |angle| > 135 backward, otherwise lateral (45 and 135 inclusive); start == end is `zero_length`.
- Progressive pass: **successful** pass whose end is at least 25% closer (metric distance, inclusive) to the attacked goal centre (100, 50) than its start. No minimum-distance or own-half rule is applied; unsuccessful passes are never progressive.
- Completion rates are `None`/NaN when nothing was attempted; no zero-filled rates.
